# Writeup: «КуМир за стеной»

## 1. Разведка

По легенде — «робот упёрся в стену, исследуйте форум “Клеточка”». Открываем `kumir-behind-the-wall.solarctf.ru` — на вид обычный форум школьного кружка по программированию, ничего особенного.

К заданию приложен `docker-compose.yml` — смотрим его первым. Внутри два сервиса:

- **web** — сам сайт, тот, что видим мы.
- **kumir-checker** — сидит во внутренней сети `govnonet`, порт 8081, снаружи недоступен.

То есть сам я до `kumir-checker` не достучусь, а вот `web` — вполне, он в той же сети. Значит, нужно заставить `web` сходить туда вместо меня.

## 2. Где дыра

Листаем форум дальше и в профиле находим «Аватарку по ссылке»: вставляешь URL — сервер сам идёт и качает картинку. Классический SSRF — запрос улетает от лица сервера, и если он не фильтрует, куда ему можно ходить, можно подсунуть любой внутренний адрес.

На самом форуме есть тема от `marya_sergeevna` — учительница пишет, что у задания `robot-final` потерялся эталонный ответ, но зато «на неверный ответ проверяльщик пишет подробно, специально для преподавателя». Админ `admin_7b` в ответ скидывает адрес: `http://kumir-checker:8081`. Вот и готовая подсказка, куда стучаться.

## 3. Эксплуатация

Дальше задача простая: сделать так, чтобы `web` сходил к `kumir-checker` за меня и показал, что там внутри.

### Шаг 1 — разведка эндпоинта

Вставляю в поле аватарки:

```
http://kumir-checker:8081/health
```

Сайт в ответ отдаёт `303 See Other`. Иду в `/api/avatar/me` и смотрю, что реально пришло — через Network в devtools или в Burp. Там находится диагностика:

```json
{
  "diagnostic": "Kumir 2 teacher checker\nGET /teacher/check?task=robot-final&answer=<one-line answer>\n..."
}
```

Отлично, вот и путь: `/teacher/check?task=robot-final&answer=...`

### Шаг 2 — специально ошибаемся

Учительница же сама сказала: подробный разбор проверяльщик даёт именно на неверный ответ. Значит нам и нужен неверный — чтобы в отчёте всплыл эталон. Подставляю:

```
http://kumir-checker:8081/teacher/check?task=robot-final&answer=wrong
```

Нюанс: смотря как отправляешь запрос, символ `&` может порезать параметры и прилетит `400 Bad Request`. В Burp просто кодируем его как `%26` в теле POST-а, и всё ок.

### Шаг 3 — читаем ответ

Сохранили ссылку, сервер опять ответил `303` — теперь идём смотреть, что он реально притащил:

```
https://kumir-behind-the-wall.solarctf.ru/api/avatar/me
```

Так как ответ был заведомо неверный, прилетает `422 Unprocessable Entity` и нормальный такой JSON-отчёт:

```json
{
  "verdict": "WA",
  "expected": "SOLARCTF{n3_s0tv0ri_s3b3_kumir4}",
  "received": "wrong"
}
```

В `expected` лежит ровно то, что нужно.

Браузер тут может ругнуться `ERR_INVALID_RESPONSE` — он ждёт картинку, а приходит JSON. Просто смотрим ответ через вкладку Network или в Burp (HTTP history / Repeater), там всё видно.

### Флаг

```
SOLARCTF{n3_s0tv0ri_s3b3_kumir4}
```

## Как закрыть эту дыру

- **Вайтлист доменов.** Разрешить аватарки только с доверенных источников (например, gravatar.com), а не с чего угодно.
- **Блокировать внутренние адреса.** `127.0.0.1`, `localhost`, подсети `10.x.x.x`, `172.16.x.x`, `192.168.x.x` — всё это сервер не должен трогать по запросу пользователя.
- **Проверять схему URL.** Только `http`/`https`, остальное (`file://`, `gopher://`, `dict://`) — отсекать.
